# 📊 Social Media Content Analyzer

Upload a social media post (as a PDF or an image/screenshot) and get the text
extracted automatically, plus data-driven, rule-based suggestions for
improving engagement.

## Features

- **Drag-and-drop or file picker** upload for PDFs and images
- **PDF text extraction** with layout preserved (via `pdfplumber`), with
  automatic OCR fallback for scanned/image-only PDF pages
- **OCR for images** (PNG/JPG/WEBP/BMP/TIFF/GIF) via Tesseract
- **Engagement analysis**: word count, readability score, hashtag/mention/
  link/emoji detection, hook strength, call-to-action detection — each with
  an actionable suggestion
- Loading states and clear error handling on both frontend and backend
- No paid API keys required — everything runs locally/offline

## Tech Stack

- **Backend:** Python, Flask, `pdfplumber` (PDF parsing), `pytesseract` +
  Tesseract OCR (image text extraction), Pillow
- **Frontend:** Vanilla HTML/CSS/JavaScript (no build step, no framework
  dependency — keeps the project minimal per submission guidelines)

## Setup & Run Locally

### Prerequisites
- Python 3.10+
- [Tesseract OCR engine](https://github.com/tesseract-ocr/tesseract) installed
  and on your `PATH`
  - macOS: `brew install tesseract`
  - Ubuntu/Debian: `sudo apt install tesseract-ocr`
  - Windows: install from the [UB-Mannheim build](https://github.com/UB-Mannheim/tesseract/wiki)

### 1. Backend

```bash
cd backend
python3 -m venv venv
source venv/bin/activate      # Windows: venv\Scripts\activate
pip install -r requirements.txt
python app.py
```

The API will start on `http://127.0.0.1:5000`.

### 2. Frontend

The frontend is plain static HTML/CSS/JS — no build step needed.

```bash
cd frontend
python3 -m http.server 8080
```

Then open `http://127.0.0.1:8080` in your browser.

> If you deploy the backend elsewhere, update `API_BASE_URL` in
> `frontend/config.js` to point at it.

## How It Works

1. **Upload** — the frontend validates file type/size, then POSTs the file
   to `POST /api/analyze` as `multipart/form-data`.
2. **Extraction** — the backend detects PDF vs. image:
   - PDFs are parsed page-by-page with `pdfplumber` (layout-aware). Any
     page with no extractable text (i.e. a scanned page) is rendered to an
     image and passed through Tesseract OCR automatically.
   - Images go straight to Tesseract OCR.
3. **Analysis** — the extracted text is run through a transparent,
   rule-based analyzer (no external AI call) that checks: length,
   readability (Flesch Reading Ease), hook strength, presence of a call to
   action, hashtag count, question marks, emoji usage, and raw links.
4. **Response** — the API returns extracted text, stats, and a list of
   categorized suggestions (`good` / `low` / `medium` / `high` severity),
   which the frontend renders with loading and error states handled
   throughout.

## Approach Write-up (for submission)

This project extracts text from social posts (PDF or scanned image) using
`pdfplumber` for PDFs and Tesseract OCR for images, with automatic OCR
fallback when a PDF page has no embedded text layer. Rather than calling a
paid AI service, engagement suggestions are generated by a transparent,
rule-based analyzer checking readability, hook strength, CTA presence,
hashtag usage, and similar signals — this keeps the app fully free-tier and
explainable. The backend is a small Flask API with clear error handling
(unsupported types, oversized files, extraction failures) and the frontend
is dependency-free vanilla JS with drag-and-drop upload and loading states,
keeping the codebase easy to review and the repo free of unnecessary
dependencies per the submission guidelines.

## Notes / Possible Extensions

- Swap the rule-based analyzer for an LLM call (e.g. a free-tier API) behind
  the same `analyze_engagement()` interface if richer, model-based
  suggestions are wanted later.
- Add multi-file batch upload.
- Persist analysis history (currently stateless, in-memory only).
